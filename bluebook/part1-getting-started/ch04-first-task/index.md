# 第 4 章 快速完成第一个 WorkBuddy 任务

理论到此为止。这一章，我们直接跑通一个**能验收**的小任务。

## 选一个低风险、见效快的任务

推荐新手第一个任务：**把一段杂乱的要点，整理成一份结构清晰的会议纪要**。

在对话区输入（可直接复制）：

```
帮我把下面这些散乱要点整理成一份会议纪要，包含：
1. 会议主题与日期
2. 核心结论（3 条以内）
3. 待办事项（负责人 + 截止时间，没有就标注「待定」）
4. 需要澄清的开放问题

要点：
- 周三和产品对了一下 Q3 规划
- 决定先做数据看板，再接自动化报表
- 小李负责看板，周五前出初版
- 预算还没批，要等老板签字
- 大家都觉得周报太花时间，想用模板
```

## 你会看到什么

1. WorkBuddy 把目标拆成步骤（定结构 → 归类要点 → 补负责人/时间 → 列开放问题）。
2. 在结果区生成一份 Markdown / 文档。
3. 你可以要求「改成表格形式」「加一句总结语」继续迭代。

## 验收标准（先想好怎么算「做对了」）

- [ ] 四部分齐全
- [ ] 待办都带上了负责人和时间（缺失处标「待定」）
- [ ] 开放问题单独列出，没有混进结论

::: tip 第一个任务的三个要点
1. **任务要小**：先拿低风险内容练手。
2. **验收要早**：先说清「怎样算完成」，比事后挑刺高效。
3. **大胆迭代**：产物不对就接着说，WorkBuddy 擅长在对话里改。
:::

::: warning 别一上来就交真文件
第一次先用示例文本。等熟悉了「下指令—验收—迭代」的节奏，再让它动你真实的文档。
:::
